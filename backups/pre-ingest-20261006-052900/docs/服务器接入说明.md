# EnvMon 服务器接入说明（能不能填 https 地址？）

版本：20261006-v1.0
适用固件：`esp32-4spi-st7735s-tft-v2.0.0`（TFT7735 2.0.0）

---

## 一、结论先行

**不能。** 配网页的"服务器地址"里**不要填 `https://...`**，只填**主机名或 IP**，且该地址**必须是明文 HTTP 可达的**。

原因是固件里三处硬编码：

```cpp
// main_esp32s3_tft7735.cpp:57~65
WiFiClient client;                                    // ← 明文客户端，不是 WiFiClientSecure
HTTPClient http;
String url = String("http://") + String(g_cfg.mqtt_host)   // ← 协议写死 http://
           + ":" + String((int)g_cfg.http_port) + "/api/telemetry";  // ← 路径写死
http.begin(client, url);
```

| 限制 | 后果 |
|---|---|
| 协议写死 `http://` | 不支持 https；host 里填 `https://xxx` 会拼成 `http://https://xxx:443/...` 直接失败 |
| 用 `WiFiClient`（非 `WiFiClientSecure`） | 无法建立 TLS，443 端口打不通 |
| 路径写死 `/api/telemetry` | 路径不可配置 |
| `http_port` 必填 | 填 443 会以**明文 HTTP** 去连 443，必然失败 |

`MAX_HOST_LEN = 64`，域名长度不是问题（目标域名 33 字符，够）。

## 二、配网页正确填法

| 字段 | 填什么 | 示例 |
|---|---|---|
| 服务器地址（IP 或域名） | **只填主机名/IP，不带协议** | `192.168.2.220` |
| MQTT 端口 | MQTT 服务端口（无 MQTT 可留默认） | `18830` |
| **HTTP 端口** | **服务端明文 HTTP 端口** | `8222`、`12090` 等 |
| 接入模式 | 选"手动指定"，否则会走局域网自动发现覆盖配置 | — |

## 三、对 `https://8ee1630c307b-0.hotyuo161.fnos.net/` 的实测

2026-10-06 实测结果：

| 项目 | 结果 |
|---|---|
| DNS 解析 | `111.63.185.152` |
| TCP 443 | ✅ 开放 |
| TCP 80 / 8080 / 12090 / 18830 | ❌ 全部不可达 |
| TLS 握手 | ✅ TLSv1.3，证书 `hotyuo161.fnos.net`，有效期至 2026-11-22 |
| HTTPS 请求任意路径 | **HTTP 403**，返回"FN Connect 访问提示"页（alt="无权限图标"），`Server: nginx` |

**两个独立问题叠加：**

1. **协议问题**（固件侧）：只开 443 且是 https，固件是明文 http → 对不上。
2. **权限问题**（服务器侧）：403 是飞牛 FN Connect 网关的**未授权拦截页**，不是 404。说明该穿透域名当前**未对匿名请求开放**，需要在 fnOS 后台配置（开启外网访问 / 设置允许匿名 / 配置访问口令）。**即使固件支持 https，现在也会被 403 挡住。**

> 顺序很重要：先解决 403（服务端授权），再解决协议（转发或改固件）。只打通一边都没用。

## 三之二、二次实测（2026-10-06 凌晨）—— 关键进展

用户在浏览器里访问 `https://8ee1630c307b-0.hotyuo161.fnos.net/api/telemetry`，返回：

```json
{"detail":"Method Not Allowed"}
```

**这一句信息量很大：**

| 推断 | 依据 |
|---|---|
| 权限已经通过了 | 不再返回 FN Connect 的 403 拦截页，而是**到达了应用本身** |
| 服务端是 **FastAPI** | `{"detail":"..."}` 是 FastAPI 的默认错误体，405 是它的默认 Method Not Allowed |
| `/api/telemetry` **接口存在**，且**只接受 POST** | 浏览器是 GET，所以被 405 拒 |
| ⚠️ 固件用的正是 POST | 说明**接口方法对得上**，只剩协议和鉴权两道坎 |

**但同时我（脚本，无身份）去请求，仍然 403。** 说明 FN Connect 的放行是**基于身份/会话**的（你的浏览器已登录或持有凭证），**匿名客户端一律被拦**。这带来两个后果：

1. ESP32 直接走这个外网域名 **不可行**（既要 TLS，又要身份）。
2. 我们写的中继转发器当**匿名代理**也不行——它同样会被 403 挡。**除非**中继能带上有效凭证（cookie/token），这需要先弄清 FN Connect 的鉴权方式。

**另外**：`192.168.2.220` 目前**离线**（ping 不通、ARP 表无记录），本机 `192.168.2.218`，同网段未见 EnvMon 服务监听。

**因此结论收敛为：走内网直连最实际**——需要知道 EnvMon 服务端所在设备（飞牛 NAS？）的**局域网 IP + 明文 HTTP 端口**。

## 四、三条可行路径

### 路径 A：局域网直连（最省事，推荐先验证）

如果服务端就跑在你的 Docker 宿主机 `192.168.2.220:8222` 上，且设备与它在同一局域网：

- 服务器地址填 `192.168.2.220`
- HTTP 端口填 `8222`（或实际端口）
- 不需要 https，不需要穿透，不需要转发器

先这样跑通，确认固件上报链路正常，再考虑外网。

### 路径 B：转发器（不改固件、不烧录）

在一台与 ESP32 同网、长时间开机的机器上跑 `tools/telemetry-relay/telemetry_relay.py`：

```
ESP32 --明文http--> 转发器:12090 --https--> https://8ee1630c307b-0.hotyuo161.fnos.net
```

```bash
python telemetry_relay.py --port 12090 --target https://8ee1630c307b-0.hotyuo161.fnos.net
```

固件侧：服务器地址填**运行转发器那台机器的局域网 IP**，HTTP 端口 `12090`。
纯标准库，无需 pip 安装。⚠️ 前提仍是服务端 403 已解决；Windows 上需放行防火墙对应端口。

### 路径 C：改固件支持 https（一劳永逸，需自行编译）

把 `WiFiClient` 换成 `WiFiClientSecure`：

```cpp
#include <WiFiClientSecure.h>
WiFiClientSecure client;
client.setInsecure();          // 跳过证书校验（测试用）
String url = String("https://") + String(g_cfg.mqtt_host) + ":" + String(g_cfg.http_port) + "/api/telemetry";
```

本机无 espressif32 工具链，需用 Arduino IDE 自行编译上传。代价是会覆盖已验证的 v2.0.0 正式固件，建议先在路径 A/B 验证通了再改。

## 五、排查顺序

1. 浏览器直接访问 `https://<域名>/api/telemetry` → 若仍是 403，说明服务端授权没开，先去 fnOS 后台处理。
2. 服务端 200 之后，再决定用路径 A（局域网）还是 B（转发器）。
3. 固件侧确认上报成功：串口会打 `[HTTP] telemetry OK seq=...`；失败则是 `[HTTP] telemetry FAIL code=xxx`。
   ⚠️ 该固件应用模式关闭 USB CDC，日志走硬件 UART0（GPIO43/44），需外接 USB-TTL 才能看到。
