## 二、回退速查

```bat
:: 回退到 v2.0.0（EnvMon，含血氧）
esp32-4spi-st7735s-tft-v2.0.0\flash.bat COM9

:: 回退到 v1.0.0（EnvMon 基础版，最稳）
esp32-4spi-st7735s-oled\flash.bat COM9
```

手工命令（脚本内部就是这两步，**必须先擦除**）：

```bash
esptool --chip esp32s3 --port COM9 erase-flash
esptool --chip esp32s3 --port COM9 --baud 115200 write-flash \
  0x0 bootloader.bin 0x8000 partitions.bin 0x10000 firmware.bin
```

> ⚠️ 不做 `erase-flash` 直接覆盖写，会因旧固件残留报 `MD5 of file does not match data`。

## 四、为什么 XD-58C 用 GPIO2

1. **GPIO2 是空闲 ADC**：v2.0.0 固件里 `ADC1_CH2` / `PPG` 均未实现（字符串取证确认），这个脚一直空着；固件实际只用了 GPIO4=ADC1_CH3（MIC）。
   （ESP32-S3 通道映射：**GPIO1=CH0、GPIO2=CH1**、GPIO3=CH2、GPIO4=CH3。）
2. **必须用 ADC1（GPIO1~10）**：ESP32 的 **ADC2（GPIO11~20）与 Wi-Fi 冲突**，Wi-Fi 开启后读不了，固件会报 `ADC2 is in use by Wi-Fi`。本固件全程开 Wi-Fi，所以只能选 ADC1。
3. **用途吻合**：`docs/01` 里 GPIO2 本就规划为"脉搏 PPG 输入"。
4. **不侵占 MAX30102**：GPIO2 与 GPIO14/13 毫无关系，MAX30102 接线原样不动。

## 六、服务器上报接入（要点，详见 `docs/服务器接入说明.md`）

| 项 | 结论 |
|---|---|
| 配网页"服务器地址" | **只填主机名或 IP**，不能带 `https://` |
| 协议支持 | ❌ **不支持 https**。固件硬编码明文 `http://` + `WiFiClient` |
| 上报路径 | 写死 `/api/telemetry`，不可配置 |
| HTTP 端口 | 必须填服务端**明文 HTTP** 端口；填 443 会以明文连 TLS 端口，必然失败 |
| 外网 https 域名 | 需走 `tools/telemetry-relay/` 转发，或改固件用 `WiFiClientSecure` |

实测 `8ee1630c307b-0.hotyuo161.fnos.net`：
- 仅 443 开放（TLS1.3）
- 匿名请求（脚本/设备）→ **403「FN Connect 访问提示 / 无权限」** 拦截页
- 已登录的浏览器 GET → `{"detail":"Method Not Allowed"}` → **服务端为 FastAPI，`/api/telemetry` 存在且只收 POST**（固件用的正是 POST，方法对得上）
- ⚠️ 放行按身份/会话，**匿名客户端一律 403**，故 ESP32 与中继都不通，**结论：走内网直连**

### 设备怎么知道服务器在哪？（自动发现机制，见 `docs/设备发现与接入方案.md`）

固件上电若未指定服务器，会向多播组 **`239.255.1.1:12091`** 每 4 秒广播探针，
服务端应答 `{"ip":..,"port":..,"user":..,"pass":..}`，设备存 NVS 后重启上报；45 秒无应答退回 AP 配网。

| 项 | 原版固件 | 打了 pid 补丁后 |
|---|---|---|
| 探针 | 裸 `"ENVMON?"`（**无身份**） | `{"probe":"EnvMon","pid":"clinic-a","did":"esp32-4d3f54"}` |
| 多项目共存 | ❌ 所有服务器都应答，设备会串项目 | ✅ 只登记了该 pid 的服务器应答，其余**静默** |
| 服务端 | 无（缺失） | `services/beacon_server.py` + `projects.json` |

> 要点：`default` 保持 `null` 是多项目共存的关键；同一网段多个项目时不要开。
> Docker 部署必须 `--network host`，否则收不到多播。
