## 二、发现列表（按临床风险）

### 🔴 危及患者安全

**S1. AI 评估无"数据来源"标注 —— 医师无法判断结果可靠性**
- 当前返回示例：`overall_risk: "critical"`，但医师无法看到是"基于 24 条体征 + 3 条检验"还是"仅基于 1 条体征"
- 临床要求：评估结果旁必须明确标注 **数据窗口内 vitals 条数 / 最后更新时间 / 缺失参数列表**
- 实测：`vitals_count: 24, orders_active: 3, labs_recent: 7` 已返回 ✅
- **但 UI 实时监护面板未展示这些元数据** —— 医师不知道 24 条体征是 5 分钟前还是 5 小时前
- 修复：UI 展示 `last_vital_at` / `data_gap_minutes`

**S2. 危急值（CRIT）触发逻辑在服务器端 vs 检验 LIS 端可能不同步**
- 实测：pH 7.28 → `critical=1` ✅
- 但当前算法仅基于 `ref_min / ref_max` 差值范围计算，**未考虑项目特异性**
- 临床要求：pH 危急值应为 **<7.20 或 >7.60**（固定阈值），而非基于参考区间偏移
- 实测 pH 7.22 → 也 `critical=1`（当前逻辑）—— 这个恰好符合，但**是偶然正确**
- 风险：如果 LIS 传入 `ref_min:7.35, ref_max:7.45`（正常参考区间），而真实危急区间是 `<7.20`，两者差 0.15，算法会把 pH 7.28 标为危急（过激）
- 建议：`lab_results` 增加 `crit_min/crit_max` 独立字段，与 ref 解耦

**S3. GCS（格拉斯哥昏迷评分）无采集 —— 神经系统评估为空白**
- 8 系统中 `neuro` 永远返回 `"GCS 未接入，请人工评估"`
- ICU 患者昏迷评分是核心指标，长期缺失会导致 `overall_risk` 低估
- 建议：UI 增加 GCS 手动录入入口（3E + 4V + 6M = 13 分）

**S4. 无报警确认 / 消警流程 —— 护士无法标记"已处理"**
- 报警列表只有 `ts / cleared_at`，无 `ack_by / ack_at`
- 临床场景：报警频繁，护士处理一条后应能标记"已确认"，避免重复报警疲劳
- 建议：`POST /api/alarms/{id}/ack` + `GET /api/alarms?ack_only=true`

---

### 🟠 临床可用性

**U1. 出入量界面缺少"每班小结"功能 —— 护士每班交接需手动计算**
- ICU 每班 8 小时，需要"本班入 / 本班出 / 累计净"三组数字
- 当前只有 24h 汇总，无班次切换
- 修复：`GET /api/patients/{pid}/io/balance?hours=8&shift_start=...`

**U2. 医嘱无"执行记录" —— 实际给药时间与医嘱时间脱节**
- 当前 orders 只有 `start_ts/end_ts`（医嘱时间），无 `administered_at`（执行时间）
- 临床要求：实际执行时间、执行人、剩余量（泵）均需记录
- 建议：新增 `order_executions` 表或扩展 `orders` 表

**U3. 检验结果无"趋势箭头"或"与上次对比"—— 医师看化验单效率低**
- 当前 UI 只显示单条 value + ref 区间
- 临床习惯：`K 4.5 (↑ from 4.2)` 这样带趋势
- 修复：`lab_results` 查询时附带上一值做 diff

**U4. 体征卡缺"报警静默"功能 —— 已处理的异常仍然闪红**
- 医师处理完异常（如调整吸氧后 SpO2 恢复）仍需系统重新评估才去红
- 建议：手动静默 + 定时解除

**U5. AI 评估无"上一版本对比"—— 医师无法判断病情是好转还是恶化**
- 每次 GET 都是独立评估，无版本历史
- 建议：`assessment_log` 表记录每次评估结果，`GET /api/patients/{pid}/assessment/history?hours=24`

---

### 🟡 数据完整性

**D1. 无患者身份二次确认 —— 可能录错患者**
- 录入 vitals/lab/io 时只凭 `pid`，无二次确认（如扫描腕带）
- 临床要求：录入时弹出"请确认患者姓名 + 床号 + 住院号"
- 修复：UI 录入表单顶部展示患者完整信息

**D2. 无数据修订 / 撤销机制 —— 录错无法更正**
- 所有 vitals/lab/io 只有 POST 无 PUT/DELETE
- 护士录错出入量无法撤销（只能再录一条反方向，污染净平衡）
- 建议：`DELETE /api/patients/{pid}/io/{io_id}` 或软删除 `status='voided'`

**D3. 检验危急值无"通知临床"机制 —— 结果入库但不告警**
- LIS 录入 pH 7.28 后仅 `critical=1`，但**不会触发报警栏位**或推送消息
- 临床要求：危急值应立即推送给主管医生（手机/桌面）
- 建议：`POST /api/patients/{pid}/lab` 时若 `critical=1` 则广播 WebSocket `type:critical_lab`

**D4. 设备离线后体征卡显示"最近值"但不显示"数据缺失时长"**
- 医师看到的是最后一次值，不知道已经失联多久
- 建议：`last_seen` 超过阈值时显示红色 "数据丢失 47 分钟"

---

### 🔵 用户体验

**X1. AI 评估 disclaimer 每次都在页面固定位置 —— 视觉干扰**
- 当前 disclaimer 每 24h 都展示，占用 UI 空间
- 建议：折叠到 tooltip 或点击展开

**X2. 中文数字与单位混排 —— 阅读体验差**
- UI 中 `1275.0mL` `325.0ml` 单位大小写不一致
- 建议统一为 `mL`（小 m 大 L，国际标准）

**X3. 出入量录入界面"子类"自由文本 —— 无法统计汇总**
- 护士输入 "生理盐水"、"盐水"、"NS" → 系统无法聚合
- 建议：下拉选择预设子类 + 允许自定义

**X4. 无批量操作 —— 录入多条出入量需重复弹窗**
- 交接班时通常有 5–10 条出入量要录
- 建议：批量录入模式

## 四、合规提示

1. **本系统不能替代临床判断**（disclaimer 已写明 ✅）
2. **不建议存储明文密码 / 患者 PII** —— 当前 `password` 用 PBKDF2（✅），`patients` 表无脱敏（⚠️ 需评估）
3. **建议**：评估结果保留审计日志，满足医疗事故追溯要求
4. **FDA / 药监局分类**：如用于正式临床决策需按医疗器械 II 类以上审评，当前代码仅为科研/教学
