# 05 · 故障排查与维护 (v2.2)

按"现象 → 定位 → 处理"组织。先看 LED 颜色（最快），再看屏幕，再看服务器日志。

## LED 速查

| LED | 含义 | 处理 |
|-----|------|------|
| 绿色呼吸 | 正常 | — |
| 青色呼吸 | AP 配网 | 见《03》 |
| 橙色闪烁 | LV1 预警 | 检查环境/阈值 |
| 红色快闪 | LV2 报警 | 查仪表盘+报警记录 |
| 红色脉冲 | 体征危急（HR/SpO₂ 异常） | 立即临床评估 |
| 蓝色慢闪 | 传感器无数据 | 见传感器节 |
| 不亮 | 未供电或接线错 | 查供电与 LED 共阴接法 |

## 传感器问题

- **屏幕 `--` + 蓝灯**：I2C 未读到。查 AHT20/BMP280 的 VCC/GND/SDA(8)/SCL(9)，长导线加 4.7kΩ 上拉
- **ECG/PPG/Breath 读数为 0 或噪声极大**：前端调理电路未接入或未校准，见《01》
- **温度偏高**：AHT20/BMP280 靠近发热元件，远离
- **气压漂移**：随海拔天气正常变化，可对照气象站

## 网络 / MQTT

- **状态点红（OFF）**：未连 WiFi。查路由器
- **状态点黄（WIFI）**：WiFi 通但 MQTT 不通。查 18830 端口、账号密码
- **60 秒后回落 AP**：WiFi 信息错误或路由器异常 → 手机重连 AP 重新配网

## AI 评估异常

- **评估显示 🔴 危急但患者无异常**：
  - 检查体征传感器是否接入/校准（未接入时读数随机 → 触发阈值）
  - 检查检验是否录入错误的参考范围（`lab_results` 表）
- **评估显示 🟢 低但患者明显恶化**：
  - 体征数据未及时录入（`vitals` 表近 24h 无数据 → 评估用旧值）
  - 规则引擎阈值（《08》）未覆盖该临床情况 → 手动调整
- **评估结果突然变化**：
  - `hours` 参数默认 24，时间窗口内数据变化会导致结果不同
  - 出入量变化会触发 fluid 系统评分

## 数据 / 备份

- **数据库文件过大**：`telemetry_1m` 会累积。可通过 API 或手动清理（`sqlite3 envmon.db "DELETE FROM telemetry_1m WHERE ts < '<一周前>'"`）
- **备份失败**：
  - 查 `/data/backups` 目录权限（容器以 root 运行，挂载卷应可写）
  - `BACKUP_DIR` 环境变量是否正确
- **备份清理不生效**：`BACKUP_INTERVAL_DAYS` 默认 3，改 `.env` 重启容器

## OTA 升级失败

- **上传 500**：文件非 .bin 或过大
- **固件写入成功但重启后异常**：OTA 自动回滚到另一 slot
- **`/api/ota/image` 404**：服务器上无对应版本 → 重新上传

## 服务器端口

- v2.2 后端端口为 **12090**（非 8627/8000）
- MQTT 端口 **18830**
- 访问失败先确认防火墙：
  ```bash
  sudo ufw status | grep -E "12090|18830"
  curl http://127.0.0.1:12090/api/health
  ```
