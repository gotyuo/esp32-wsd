# 05 · 故障排查与维护

按"现象 → 定位 → 处理"组织。排查顺序建议：先看 **LED 颜色**（最快定位），再看屏幕，再看服务器日志。

## LED 速查

| LED 现象 | 含义 | 处理方向 |
|---------|------|---------|
| 绿色呼吸 | 一切正常 | 无需处理 |
| 青色呼吸 | AP 配网模式 | 见《03-设备配网》 |
| 橙色闪烁 | 接近阈值预警 | 检查环境或放宽阈值 |
| 红色快闪 | 超阈值报警 | 检查环境/传感器，查看仪表盘报警记录 |
| 蓝色慢闪 | 传感器无有效数据 | 见"传感器"一节 |
| 不亮 | 未供电或 LED 接线错 | 检查供电与 RGB 引脚/共阴接法 |

## 传感器问题

- **屏幕显示 `--`，蓝灯慢闪**：I2C 未读到传感器。检查 AHT20/BMP280 的 VCC/GND/SDA(GPIO8)/SCL(GPIO9) 接线；确认两者供电为 3.3V；长导线时加 4.7kΩ 上拉。
- **温度明显偏高**：AHT20/BMP280 靠近发热元件（ESP32、屏幕背光）会受烘烤，尽量让传感器远离热源并保证通风。
- **气压漂移**：气压随海拔与天气变化属正常；可对照当地气象站气压校准阈值范围。

## 网络 / MQTT

- **屏幕状态点红（OFF）/黄（WIFI）**：未连上 WiFi 或 MQTT。确认配网信息正确、路由器信号良好。
- **状态点黄（WIFI）但不绿**：WiFi 通但 MQTT 连不上。检查服务器 `MQTT_PORT`（默认 18830）可达、MQTT 账号密码一致、防火墙放行。
- **服务器端验证 Broker**：
  ```bash
  docker compose logs -f mosquitto          # 看是否有设备 connect
  # 订阅设备主题观察数据
  docker compose exec mosquitto mosquitto_sub -h localhost -u envmon -P <密码> -t 'envmon/#' -v
  ```
- **设备频繁离线/上线**：多为 WiFi 信号弱或路由器带机量不足；检查 `GET /api/devices` 的 `rssi`（优于 -70 dBm 为佳）。

## 服务器

- **仪表盘打不开**：`docker compose ps` 确认 backend 为 Up；`curl http://127.0.0.1:8627/api/health`；检查防火墙 8627 放行。
- **数据不入库但有设备在线**：`docker compose logs backend` 查看 MQTT 桥是否连接成功（`MQTT connected`）。
- **修改阈值不生效**：确认设备在线（配置经 MQTT 下发）；离线设备的配置会在其上线时通过 `config/req` 自动同步。查看 `config/ack` 日志确认回执。
- **磁盘增长**：数据在 `server/data/envmon.db`；按保留策略自动清理；定期执行 `scripts/backup_db.sh`。

## 维护建议

1. **定期备份**：crontab 每日执行 `scripts/backup_db.sh`，并将 `backups/` 异地保存。
2. **固件升级**：修改代码后 `py -m platformio run` 重新编译，用 `scripts/flash_firmware.sh` 或 PlatformIO 上传；或直接用 `release/` 中的镜像烧录。
3. **日志观察**：`docker compose logs -f` 是最直接的排障入口。
4. **供电**：建议用稳定 5V/1A 以上电源；WiFi 发射峰值电流较大，供电不足会导致随机重启（看门狗复位）。
5. **长期运行**：固件已实现 WiFi/MQTT 自动重连与指数退避，掉线可自愈；若发现堆内存持续下降（`status` 命令的 heap 值），可定期重启设备。
