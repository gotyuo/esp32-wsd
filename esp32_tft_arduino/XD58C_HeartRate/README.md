| 项目 | 值 |
|------|-----|
| **版本** | **`20261006-v1.1`**（上一版 `20261006-v1.0`） |
| 日期 | 2026-10-06 |
| 适用 | ESP32-S3 + 0.96" ST7735S(160×80) + XD-58C |

> Arduino IDE 打开即可编译上传。

## ⚠️ 先搞清楚：XD-58C 不是 MAX30102

| 项目 | XD-58C（你手上这块） | MAX30102 |
|------|---------------------|----------|
| 接口 | **模拟电压输出**（3 线：+ / − / S） | **I2C**（4 线：VCC/GND/SDA/SCL） |
| 有没有 SCL | **没有**，也不需要 | 有 |
| 能测什么 | **只有心率 BPM** | 心率 **+ 血氧 SpO2** |
| 供电 | 3.3V～5V | 3.3V／模块带电平转换 |

**所以"只有一个数据输出、没有 SCL"是完全正常的**——它压根不是 I2C 器件。
它输出的是模拟电压：以 VCC/2 为基线，脉搏表现为叠加在上面的小幅波动（绿光 609nm 反射式 PPG，板载已做放大滤波）。

> 血氧 SpO2 这块模块**物理上测不了**，必须换 MAX30102。

## 一、接线

### 屏（ST7735S 0.96" 160×80）

| 屏引脚 | ESP32-S3 |
|--------|----------|
| VCC | 3V3 |
| GND | GND |
| SCK | GPIO 12 |
| MOSI | GPIO 11 |
| CS | GPIO 10 |
| DC | GPIO 7 |
| RST | GPIO 6 |
| BL | GPIO 5 |

### XD-58C

| 传感器 | ESP32-S3 | 备注 |
|--------|----------|------|
| `+` | **3V3** | ⚠️ **必须 3.3V**。接 5V 时输出摆幅到 5V，会打坏 ESP32 的 ADC 引脚 |
| `−` | GND | 共地 |
| `S` | **GPIO 2** | ESP32-S3 上 GPIO2 = **ADC1_CH1**，模拟输入 |

#### 实物定位（ESP32-S3-WROOM-1 `ESP32-S3-32-N16R8` 开发板）

这块板 **丝印是纯 GPIO 数字，没有 D 编号**（板上不存在 "D2"/"D13"，你说的 D13 就是标 `13` 的针）。

两排排针丝印（照实物抄录）：

```
上排：GND 19 20 21 47 48 45 0 35 36 37 38 39 40 41 42 2 1 RX TX 3.3 GND
下排：3V3 3V3 RST 4 5 6 7 15 16 17 18 8 3 46 9 10 11 12 13 14 5VIN GND
```

| 信号 | 在哪找 |
|---|---|
| **GPIO2（XD-58C 的 S）** | **上排**，标 `42` 与 `1` 之间那个 **`2`**（靠右侧 RX/TX 那一端） |
| GPIO13 / GPIO14（MAX30102） | **下排**最右端，`5VIN` 左侧紧挨着的 `13`、`14` |
| GPIO12/11/10/7/6/5（屏） | 都在**下排** |
| 供电 | 任意 `3V3` / `GND`（⚠ 千万别取 `5VIN`） |

> 这块板有两个 Type-C：**USB**（原生，串口日志）与 **UART**（CH 芯片）。看串口日志优先用 **USB** 口。

#### Arduino IDE 板子参数（N16R8 = 16MB Flash + 8MB **OPI** PSRAM）

| 项 | 选择 |
|---|---|
| Board | **ESP32S3 Dev Module** |
| USB CDC On Boot | **Enabled**（否则串口打印不出来） |
| Flash Size | **16MB (128Mb)** |
| PSRAM | **OPI PSRAM** ← N16R8 是 Octal，选错会启动失败 |
| Flash Mode / Freq | DIO / 80MHz |

### 为什么选 GPIO2（空闲脚，不占用 MAX30102）

- **GPIO2 是固件没用到的空闲 ADC**：v2.0.0 固件里 `ADC1_CH2` / `PPG` 均未实现（字符串取证确认），这个脚一直空着；固件实际只用了 GPIO4 = ADC1_CH3（麦克风）。
  （注：ESP32-S3 通道映射为 GPIO1=CH0、**GPIO2=CH1**、GPIO3=CH2、GPIO4=CH3。）
- **必须用 ADC1（GPIO1~10），不能用 ADC2（GPIO11~20）**：ESP32 的 **ADC2 与 Wi-Fi 冲突**，Wi-Fi 打开后 ADC2 读不了，会报 `ADC2 is in use by Wi-Fi`。而本固件全程开 Wi-Fi，所以只能用 ADC1。
- GPIO2 在 `docs/01` 里本就规划为"脉搏 PPG 输入"，与 XD-58C 用途正好对得上。
- 备选：GPIO1（原规划 ECG 心电，同样空闲）。改 `.ino` 里的 `#define PIN_PPG 2` 为 `1` 即可，其余不用动。

### MAX30102 引脚保持不动

| MAX30102 | ESP32-S3 | 状态 |
|----------|----------|------|
| SDA | **GPIO 14** | **不动** |
| SCL | **GPIO 13** | **不动** |

XD-58C 走 GPIO2（模拟量），MAX30102 走 GPIO14/13（I2C1），**两者互不影响，可以同时接**。
本程序只用了 GPIO2，没有碰 GPIO14/13。

## 四、为什么 envmon 固件不能直接读它

对已烧的 `TFT7735 2.0.0` 固件做字符串取证：

```
ADC1_CH1 / CH2  未命中   <- 固件里没有任何模拟 PPG 采集（GPIO2/GPIO3 都没被使用）
PPG / pulse / PulseSensor  均未命中
pr_hr     命中，但来自 MAX30102 的 I2C（与 sp_o2 同组上报）
ADC1_CH3  命中，但那是麦克风 MIC（GPIO4）
```

固件的 `pr_hr`（脉率）只能来自 **MAX30102 的 I2C 总线（GPIO14/13）**，没有任何 `analogRead`。
`docs/01` 里写的"脉搏 PPG → GPIO2"只是预留规划，**固件并未实现**。
所以想让 XD-58C 出数据，只能走本程序这条路（或改固件后自行编译）。

## 七、数值校验（v1.1 逐项核对代码）

分三类：**会毁掉数值的**、**会引入误差/漏检的**、**只影响观感的**。

### A. 致命：绘制阻塞采样（v1.0 的病根，v1.1 已修）

屏驱动是**软件 bit-bang SPI**，`sw_spi_write()` 每个 bit 有两次 `delayMicroseconds(1)`，
约 **3µs/bit → 约 26µs/字节**。按这个成本算：

| 操作 | 字节量 | 估算耗时 |
|---|---|---|
| `drawPixel`（CASET+RASET+RAMWR 共 11B + 2B 颜色） | 13 B | **≈ 340 µs** |
| `drawWaveStep`（每 2ms 调一次，擦+画 2 次 drawPixel） | 26 B | **≈ 680 µs**（占 2ms 的 34%） |
| v1.0 `drawHeader` 里的 `fillRect(0,0,160,32)` | **10251 B** | **≈ 270 ms** |

v1.0 每 **400ms** 调一次 `drawHeader` → **约 67% 的时间在画屏、完全不采样**。
这期间发生的搏动要等清屏结束才被识别，IBI 最多被推迟 **±270ms**。
按 800ms 间期算：`60000 / (800 ± 270)` = **55 ~ 109 BPM** —— 数值必然剧烈乱跳。
**这就是"读数不准"的主因，与传感器本身无关。**

v1.1 改法：

- 稳态**只重画变化的字符**：BPM 数字（size2，12×16 = 192px ≈ **10ms/字**，最多 3 字）；
  IBI 文本（size1，48px ≈ **2.5ms/字**，10 字 ≈ 25ms）
- 整块清屏**只在"手指状态切换"时发生一次**，而那一刻 `resetMeasurement()` 已把测量清零，
  **不会污染任何上报值**
- 结果：稳态单次绘制 ≤ 30ms 且每秒最多一次 → 对 IBI 影响 ≤30ms，
  8 个间期平均后 **BPM 误差 < 1%**

### B. 会引入误差 / 导致漏检的（v1.1 已修）

| # | v1.0 的问题 | 后果 | v1.1 做法 |
|---|---|---|---|
| 1 | 阈值复位用 `ac < thr*0.5`，而 `thr = sigMin + amp*0.55` 在 `sigMin` 为负时可能是负值 | `above` 标志无法复位 → **此后不再识别任何搏动**（数值卡住不动） | 双阈值滞回：进 `sigMin+0.65·amp`、出 `sigMin+0.35·amp` |
| 2 | 手指抬起/放回不重置测量 | 抬起前的最后一个间期与放回后的第一个搏动被拼成一个 IBI → **算出明显偏慢的 BPM** | 状态切换立即 `resetMeasurement()`；且第一个搏动只作计时起点、不成对 |
| 3 | 单个 IBI 就显示数字 | 首次数值抖动极大 | 至少累计 **2** 个 IBI 才显示 |
| 4 | 无伪迹抑制 | 一次抖动或漏检就把平均值拉偏 | 与均值偏差 **>35%** 的间期不计入平均（但仍作为新的计时起点） |
| 5 | 采样节拍用 `lastSampleUs = now` | 实际周期 = 2ms + 执行时间，采样率略低于 500Hz；被阻塞后不会重新对齐 | `nextSampleUs += 2000µs` 严格节拍；落后 >20ms 计入 `stalls` 并重新对齐 |
| 6 | IBI 用 `millis()` 计时 | 1ms 粒度，且有 32 位回绕隐患 | 改用 `micros()` + 无符号相减（**天然抗回绕**） |

### C. 只影响观感（不影响数值）

| # | v1.0 | v1.1 |
|---|---|---|
| 7 | 波形固定 200 counts 满幅（小信号是一条直线） | 按当前幅度**自动量程**（下限 30） |
| 8 | 无极性开关 | 新增 `PPG_INVERT`（0/1），实测波形反向时改 1 |
| 9 | 无调试输出 | 新增 `SERIAL_PLOT`（100Hz 输出 `ac`，供串口绘图器）+ 每 2s 一行 `[SIG]` 诊断 |

### D. 检出但**当前不会触发**的隐患（未改，避免动已验证的驱动）

`font8x16.h` 的 `ascii_1608[][]` 只覆盖 `空格(0x20) ~ '9'(0x39)` 共 **26** 个字模，
而 `ST7735::drawChar8x16()` 按 `ascii_1608[c-32]` 索引 → **遇到字母会越界读**。
本程序只使用 5×7 字体（`FONT5X7` 共 475 字节 = 95×5，**完整覆盖 0x20~0x7E**），
**从不调用** `drawChar8x16`，因此不受影响。以后若要使用 8×16 大字，需先补全字模。

### E. 结论

- **算法框架本身是正确的**：EMA 去直流 → 自适应双阈值峰值检测 → IBI 平均 → `BPM = 60000 / mean(IBI)`，
  与官方 PulseSensor 思路一致。
- **v1.0 的数值不可信**（绘制阻塞把 IBI 打歪）；v1.1 修掉后，稳态误差只剩
  采样量化（±2ms/次）与一次 ≤30ms 的重绘抖动，8 次平均后 **< 1%**。
- 精度上限说明：这是单路反射式 PPG，**不是医疗级**；BPM 可作参考，**不能用于诊断**。

## 八、怎么确认数值是对的（实测三步）

**第 1 步：看信号质量**（串口 115200，每 2s 一行）

```
[SIG] raw=2048 ac=-3 amp=126 finger=1 ibiN=5 bpm=72 stalls=0
```

- `amp` 手指放上时应大致在 **30 ~ 200**（太小说明没对准/压太紧；太大说明噪声重）
- `stalls=0` 表示采样从未被卡住；**若持续增长**，说明有东西在阻塞采样，请把该行发我
- `finger=1` 表示已识别到手指

**第 2 步：看波形极性**（把 `#define SERIAL_PLOT 1` 后重新上传，开 **工具 → 串口绘图器**，115200）

- 波形应是**周期性上升尖峰**；如果是**向下**的尖峰 → 把 `PPG_INVERT` 改为 `1`
- 若 `amp` 一直 <30：手指轻压、对准 LED（模块反面那颗绿光），换位置/换力度再试
- 核对完把 `SERIAL_PLOT` 改回 `0`（开串口输出会占采样时间、拉低精度）

**第 3 步：与手动计数对比**

- 静坐，屏上读数稳定后，自己数 60 秒脉搏次数，与 BPM 对比
- 偏差 **<5%** 属正常（PPG 与触诊本身存在差异）
- 偏差大且数值跳 → 把 `[SIG]` 那几行 + 现象发我，我按数据调参数

**可调参数速查**

| 现象 | 调哪个 |
|---|---|
| 放下手指仍显示 `Put finger on` | `FINGER_AMP_MIN` 调小（如 20） |
| 没放手指就说测到了 | `FINGER_AMP_MIN` 调大（如 60） |
| 波形上下颠倒 | `PPG_INVERT` 改 1 |
| 数值偶尔跳到极端值 | 把 `IBI_OUTLIER_PCT` 调小（如 25） |
| 出数太慢 | 把 `IBI_NEED` 改 1（会抖一些） |
